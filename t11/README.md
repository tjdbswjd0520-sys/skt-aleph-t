# BR-A 포트폴리오 사이트 (GitHub + Vercel + Python)

## 제출물
- Vercel에 배포한 공개 웹사이트 URL
- 이 폴더 전체를 압축한 코드 ZIP

Supabase/Neon 등 별도 데이터베이스는 사용하지 않습니다. GitHub에는 코드와 공개 가능한 `data.json`을 보관하고, Vercel은 변경된 사이트를 자동 배포합니다.

## 주요 파일
- `index.html`: 포트폴리오 화면
- `style.css`: 반응형 디자인
- `script.js`: 통계와 문단 후보 표시
- `data.json`: 사이트가 읽는 기록·통계·문단 후보
- `tools/update_portfolio.py`: 신규 기록 자동 갱신 프로그램
- `기록_자동갱신.bat`: Windows 실행 도우미

## 1. 자동 갱신 프로그램 사용법
1. Python 3 설치 여부를 확인합니다. 명령 프롬프트에서 `py --version`을 입력합니다.
2. 새 리추얼 TXT 파일을 저장합니다.
3. `기록_자동갱신.bat`을 실행하고 파일 경로를 입력합니다. 또는 TXT 파일을 BAT 파일 위로 끌어다 놓습니다.
4. 프로그램이 날짜별 기록을 기존 `data.json`과 병합하고 통계·문단 후보를 다시 생성합니다.
5. 웹사이트를 새로고침해 결과를 확인합니다.

명령어로 실행할 수도 있습니다.
```bash
py tools/update_portfolio.py "C:\경로\ritual-history.txt"
```
TXT 외에 JSON도 지원합니다. JSON은 기록 객체 배열 또는 `{ "records": [...] }` 구조이며 각 객체에 `date`, `status`가 필요합니다.

### 병합 규칙
- 기본값은 날짜별 병합입니다. 신규 날짜는 추가하고, 기존 날짜는 새 상태로 갱신합니다.
- 입력 파일에 없는 과거 날짜는 삭제하지 않습니다.
- `--replace` 옵션은 기존 기록을 전부 교체합니다. 특별한 이유가 없다면 사용하지 마세요.
- 실행 전 기존 `data.json`은 `data.json.bak`으로 백업됩니다.

## 2. 문단 후보 생성
기록에서 본인 행동 중심 항목만 사용합니다. 동료 피드백은 문단 후보 근거로 사용하지 않습니다.
- 자기조절력
- 대인관계력
- 자기동기부여
- 회복탄력성과 지속성

문단 후보는 실제 기록 일부를 근거로 만드는 초안입니다. AI가 사실을 추측해 쓴 완성 문장이 아닙니다. 웹사이트에서 각 후보의 근거 기록을 펼쳐 볼 수 있습니다. 공개 전에 본인의 경험과 일치하는지 검토하고, 사적이거나 부정확한 내용은 `data.json`에서 수정·삭제하세요.

## 3. 로컬 사이트 확인
`data.json`을 fetch로 읽으므로 HTML 파일을 더블클릭하지 말고 프로젝트 폴더에서 아래 명령을 실행합니다.
```bash
py -m http.server 8000
```
브라우저에서 `http://localhost:8000`을 엽니다. 종료는 `Ctrl + C`입니다.

## 4. GitHub + Vercel 배포
1. GitHub에서 새 저장소를 만듭니다.
2. 프로젝트 폴더의 파일을 저장소에 업로드합니다.
3. Vercel에서 Add New → Project를 선택하고 GitHub 저장소를 Import합니다.
4. Framework Preset은 Other를 선택하고 Deploy합니다.
5. 이후 GitHub에 커밋할 때마다 Vercel이 자동으로 재배포합니다.

별도 환경 변수, 데이터베이스, 빌드 명령은 필요하지 않습니다.

## 5. 신규 기록 공개 절차
1. BAT 파일로 신규 기록을 반영합니다.
2. 로컬 사이트에서 수치와 문단 후보를 확인합니다.
3. 후보의 근거 기록을 펼쳐 사실과 개인정보 노출 여부를 검토합니다.
4. 필요한 문장을 직접 수정합니다.
5. 검토된 `data.json`을 GitHub에 커밋합니다.
6. Vercel 배포가 끝나면 공개 URL을 확인합니다.

- 초기 데이터는 2026-09-08~2026-11-13의 44개 날짜입니다.
- 이는 과제에서 요구하는 13주 전체 기록이라고 단정할 수 없습니다.
- 초기 통계: 실천 18일, 일부 실천 8일, 미실천 15일, 평가 누락 3일.
- 63.4%는 평가가 있는 41일 중 실천 또는 일부 실천한 비율입니다.
- 원본 리추얼 TXT에는 사적인 내용이 있을 수 있습니다. 원본 전체를 공개 GitHub에 올리지 마세요.
- `data.json`도 공개될 수 있다고 가정하고 공개 가능한 정보만 넣으세요.
- 13번 앱 프로젝트 슬롯은 아직 비워 둡니다.

## 문제 해결
- `py`를 찾을 수 없으면 Python 3 설치를 확인하세요.
- TXT는 `## 2026-11-16` 날짜 제목과 `- 강점 행동: 실천했다` 상태 항목을 사용해야 합니다.
- 변경 내용이 안 보이면 브라우저에서 `Ctrl + F5`를 눌러 강력 새로고침합니다.


## 대표작 10번 논문 반영
- `LLM 레드팀 방법론 비교 연구`의 연구 목적, 질문, 방법, H1~H3 결과, 결론과 한계를 대표작 영역에 반영했습니다.
