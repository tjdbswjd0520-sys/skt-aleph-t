# 레드팀 플랜 도우미

BR-B 연구 결과 기반 애플리케이션. 10번 과제 논문 「LLM 레드팀 방법론 비교 연구」(조사일 2026-11-10)의 결과를 레드팀 계획 기능으로 옮긴 웹 앱입니다.

## 실행 방법

1. 압축을 풉니다.
2. `index.html`을 브라우저(Chrome, Edge, Safari 등)로 엽니다. 서버, 설치, 로그인, API 키가 필요 없습니다.
3. 오프라인에서도 동작합니다. 인터넷에 연결되어 있으면 글꼴(IBM Plex)만 추가로 불러오며, 못 불러오면 시스템 글꼴로 대체됩니다.

## 사용 방법

1. 왼쪽에서 점검 대상, 방어 장치, 해 본 평가, 약점의 성격, 질의 예산, 대상 모델 수, 사람 수, 기간을 고릅니다. 위쪽 예시 버튼 3개로 값을 한 번에 채울 수 있습니다.
2. 오른쪽에 사람:자동 권고 구성, 단계별 일정, 근거가 붙은 권고 목록이 즉시 바뀝니다.
3. 「계획서 텍스트 복사」로 계획서를 복사합니다.
4. 맨 아래 「근거 자료와 한계」에서 앱이 쓴 논문 수치와 참고문헌을 확인합니다.

## 논문 결과가 기능이 된 방식

| 논문이 밝힌 결과 | 앱 기능 |
| --- | --- |
| 정적 평가에서 거의 0%였던 방어 다수가 적응형 공격에서 90% 초과 (H2, 부분 지지) | 고정 공격 모음만 쓴 경우 우선 조치 경고, 방어 종류별 권고, 일정에 적응형 방어 평가 단계 추가 |
| 인간은 적은 질의로 새 접근을 찾고 자동화는 많은 시도에 강함 (H3, 지지) | 사람 전략 탐색과 자동 확장의 구성비 계산, 사람이 여럿이면 병렬 전략 권고 |
| 자동화를 쓴 쪽의 성공률 69.5% 대 47.6%, 선택 편향 있음 (H1, 부분 지지) | 약점 성격과 질의 예산에 따른 자동 비중 조정 |
| 같은 공격도 대상 모델에 따라 93.0%에서 24.0%까지 차이 | 예비 시험 단계와 모델별 측정 권고 |

권고마다 근거 수치, 주의할 점, 근거 강도(지지, 부분 지지, 참고), 출처 링크가 붙습니다.

## 한계

- 공개 논문 결과를 종합한 2차 분석에 근거하며, 직접 실험 결과가 아닙니다.
- 사람:자동 비율은 논문이 제시한 최적값이 아니라 결과의 방향을 옮긴 설계 규칙입니다.
- 가설 검증에 쓴 논문은 4편이고 H1·H2는 직접 비교한 연구가 한 편입니다. [9]는 심사 중인 프리프린트입니다.
- 공격 프롬프트나 실행 절차는 만들거나 보여 주지 않습니다. 점검 권한을 받은 시스템에만 쓰세요.

## 폴더 구성

- `index.html`: 앱 전체(HTML, CSS, JavaScript 한 파일)
- `data/`: 논문 작성 때 정리한 원자료 CSV 3개 (앱의 근거 수치가 여기서 나왔습니다)
